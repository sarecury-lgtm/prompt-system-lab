## Evidence note

Observed the raw PROMPTS.md entry for Linux Terminal. It asks the model to act as a Linux terminal, treats user messages as commands, returns only terminal output in one code block, forbids explanations, and reserves curly braces for non-command English. Synthesis: this is a direct interface-emulation pattern.

## Short excerpt

The prompt constrains replies to terminal output only and defines how commands versus meta-language are supplied.

## Structure summary

Emulated interface role, user-command protocol, output-only code block, no explanations, escape syntax for natural language.

## Pattern lesson

Interface emulation works by turning the conversation into a narrow protocol with accepted inputs and a fixed output channel.

## Mechanism

The prompt maps user text to terminal commands and prevents ordinary assistant behavior by banning explanations and unsolicited commands.

## Failure mode

If the protocol lacks an escape hatch or output boundary, the model may explain, narrate, or execute the wrong conversational mode.

## Reusable move

Define the interface being simulated, the exact input grammar, the only permitted output format, and a separate channel for meta-instructions.

## Safety / reproduction note

For real terminals, this pattern should stay simulated unless command execution is explicitly sandboxed and authorized.
