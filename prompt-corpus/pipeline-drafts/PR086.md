## Structure summary

The README explains why project rules exist, where to install them, and lists many reusable rule templates by stack and domain.

## Pattern lesson

Persistent project instructions work best when they are stored as repo-local rule files scoped to project, file type, framework, or workflow.

## Mechanism

Rules are loaded from a conventional project path and provide reusable guidance on architecture, libraries, standards, constraints, testing, and review expectations.

## Failure mode

Without scoped project rules, the assistant relies on generic coding knowledge and repeatedly needs the same corrections for local conventions.

## Reusable move

Create .cursor/rules/*.mdc files that encode local architecture, preferred libraries, security/testing conventions, and workflow expectations for the target codebase.
