## Pattern lesson

Persistent project instructions should define scope, tool boundaries, edit protocol, and fallback behavior before task-specific work begins.

## Mechanism

Standing instructions shape every later user request by routing when to search, read, edit, validate, ask, or stop.

## Failure mode

If persistent instructions are broad but lack boundaries, the agent may over-call tools, edit without context, or continue after validation uncertainty.

## Reusable move

Write project instructions as durable operating rules: context sources, tool eligibility, read-before-edit triggers, validation limits, and when to ask the user.

## Safety / reproduction note

Leaked prompt archives should be used cautiously and attributed as historical evidence, not as authoritative vendor documentation.
