## Evidence note

Observed the OpenAI Evals repository and its docs directly. The repo defines evals as a framework and registry, documents JSONL samples with reference answers, model-graded templates, choice strings/scores, meta-evals, accuracy metrics, and contribution criteria requiring clear signal and rubrics.

## Short excerpt

Docs describe datasets, eval registration, running evals, model-graded prompts, choice labels, metascore accuracy, and criteria such as clear signal or exhaustive rubrics.

## Structure summary

Dataset plus eval template plus metric: samples contain inputs and ideals; templates score exact, fuzzy, JSON, or model-graded outcomes; meta-evals check judge quality.

## Pattern lesson

An Evaluation Rubric should be executable: define samples, expected answers or judge choices, parsing rules, metrics, and regression-friendly versions.

## Mechanism

Structured datasets and YAML/Python eval definitions convert subjective prompt quality into repeatable runs with recorded metrics such as accuracy, choice scores, and metascore accuracy.

## Failure mode

Rubrics fail when the right behavior is not directionally clear, when judge outputs are not parsable, or when model-graded evals lack human labels/meta-eval checks.

## Reusable move

For each prompt pattern, create JSONL examples with inputs and ideal behavior, register a versioned eval, choose a scoring template, and add human-labeled judge checks when using model grading.

## Safety / reproduction note

Model-graded evals still need calibration; the docs recommend meta-evals because judge prompts can be wrong even when they are structured.
