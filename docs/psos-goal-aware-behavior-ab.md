# PSOS Goal-aware Behavior A/B

범용 프롬프트 위에 공통 행동 원칙을 추가했을 때 실제 답변이 좋아지는지 확인한다. 문구가 그럴듯한지보다 같은 모델이 같은 상황에서 보이는 질문·추천·판단·다음 행동의 차이를 본다.

## 비교 대상

```text
baseline
└─ 현재 요청에 답하라는 중립 지시만 사용

goal_aware
└─ 중립 지시 + configs/psos-goal-aware-assistant-policy.md
```

두 후보는 같은 모델, reasoning effort, 상황 자료와 사용자 메시지를 사용한다. web search는 끄고 read-only sandbox에서 실행한다.

## 첫 통제 실험

검증한 행동은 다음과 같다.

- 목표가 불분명하면 핵심 질문 1~2개를 먼저 하는가
- 목표가 이미 분명하면 불필요한 질문 없이 진행하는가
- 더 좋은 자료·입력·도구가 필요할 때 스스로 요청하고 이유를 알리는가
- 사용자가 원하는 결론에 맞추지 않고 근거로 판단하는가
- 제품·식품에서 사양표보다 사용자에게 중요한 실제 경험을 적절히 보는가
- 유명한 1차 연결을 넘어 필수 의존 관계와 병목을 찾는가
- 말투와 길이 취향은 반영하되 사실 판단까지 뒤집지 않는가
- 간단한 요청을 거창한 분석으로 키우지 않는가

사례는 복숭아, 차트, 헤드폰, 미래 산업 공급망, 사실 판단 유지, 단순 문장 수정의 8개 통제 상황으로 구성했다.

### 관찰 결과

사람의 블라인드 비교에서는 goal-aware 후보가 대체로 더 선호됐다. 다만 차이의 상당 부분은 답변의 구조와 가독성에서 나타났고, 추천 대상·핵심 정보량·최종 판단이 크게 달라진 사례는 적었다.

따라서 첫 실험은 다음만 지지한다.

- 공통 정책이 질문 여부와 답변 정리를 망치지 않으면서 약간 개선할 가능성이 있음
- 단순 요청 과잉 확장과 사용자 결론 추종을 막는 guard는 유지할 가치가 있음

다음 주장은 아직 검증되지 않았다.

- 공통 정책이 실제 추천 정확도나 정보 발견 능력을 크게 높임
- 정책을 길게 만들수록 판단력이 계속 좋아짐
- 자동평가 점수가 실제 사용자 선택을 대신할 수 있음

## 추천·행동 품질 실험

두 번째 실험은 문장 품질보다 실제 선택 차이를 보기 위해 다음 6개 사례를 사용한다.

- 맛의 고점을 우선하는 복숭아
- 실패 확률을 우선하는 복숭아
- 실제 취향에 맞는 장바구니 세 개
- 소비 패턴을 계산한 체크카드
- 상승 뒤 손절 기준 갱신
- 실제 거주 조건에 맞는 집

평가자는 다음을 직접 고른다.

1. 실제로 더 따르고 싶은 답변
2. 추천·행동, 핵심 근거, 표현 중 무엇이 달랐는지
3. 실제 선택이나 행동이 달라질 정도인지

사람 평가에서는 A 3개, B 2개, 동률 1개로 한쪽이 약간 우세했지만, 추천 대상 자체가 달라진 경우는 적었다. 이 결과로 공통 정책을 더 길게 확장하지 않는다. 정책은 짧은 공통 guard와 의사결정 절차로 유지하고, 도메인별 판단력은 각 전용 프롬프트의 자료·절차·검증 기준에서 개선한다.

## 현재 정책 방향

`configs/psos-goal-aware-assistant-policy.md`는 다음을 중심으로 유지한다.

- 결과가 달라질 때만 질문 1~2개
- 충분하면 바로 진행
- 사용자 취향은 기준으로 쓰되 사실·가정·원하는 결론은 독립 검토
- 여러 선택지에서는 가능한 경우 하나의 추천이나 다음 행동을 제시
- 실사용 경험, 실패 위험, 되돌리기 어려운 손실을 실제 선택에 연결
- 숨은 비용·병목·반대 근거는 결론을 바꿀 때만 확인
- 같은 결론을 더 길게 쓰는 것을 개선으로 보지 않음
- 단순 요청은 그대로 단순하게 처리

## 실행

첫 통제 실험:

```powershell
python -B .\scripts\problem_solving_goal_aware_behavior_ab_compat.py
```

추천·행동 품질 실험:

```powershell
python -B .\scripts\problem_solving_recommendation_impact_ab.py
```

두 스크립트는 실험 답변 생성에 Codex CLI를 사용한다. 정책을 적용한 최종 프롬프트 파일만 만들 때는 Codex가 필요 없는 결정론적 렌더러를 사용한다.

```powershell
python -B .\scripts\problem_solving_prompt_renderer.py `
  --ledger .\path\to\goal-ledger.json `
  --brief .\path\to\prompt-build-brief.json `
  --output .\final-prompt.md
```

자세한 사용법은 `docs/psos-deterministic-prompt-renderer.md`에 있다.

## 평가 원칙

- 사람의 블라인드 비교를 1차로 사용한다.
- 자동 평가는 회귀 신호일 뿐 최종 판정으로 사용하지 않는다.
- 길이는 과잉 개입을 감시하는 보조 지표다.
- 표현 선호와 실제 행동 변화를 따로 기록한다.
- 정책 수정은 실제 실패 행동과 연결된 최소 변경만 한다.
- 공통 정책이 해결하지 못하는 도메인 판단 문제는 전용 프롬프트에서 고친다.

## 채택 기준

현재 정책은 범용 기본 guard로 잠정 채택할 수 있지만, 그 자체를 고성능 추천 엔진으로 간주하지 않는다. 이후에는 정책 전체 A/B를 매번 반복하지 않는다.

- 공통 정책을 크게 바꿀 때만 전체 회귀 실험
- 작은 수정은 관련 사례 2~3개만 재검사
- 실제 추천 품질은 사용자의 실제 자료와 선택 결과로 별도 검증
- 프롬프트 생성 마지막 단계는 가능한 경우 결정론적 렌더러로 재현
