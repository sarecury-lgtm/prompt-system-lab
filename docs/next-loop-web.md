# PSOS 자동 실행 화면

평소에는 요청 하나만 입력한다. 화면이 요청을 읽고 다음 실행 방식 중 하나를 추천하고 제출 시 자동 적용한다.

```text
일반 해결
최신 조사
후보 비교
프롬프트 제작
파일 변경
```

추천·구매·선택 요청은 다음 수렴 루프를 사용한다.

```text
요청
→ 정보원 정찰
→ 후보 작업대
→ 사용자 한 줄 교정
→ 재정렬 / 필터 / 부분 재조사 / 검증
→ 조사 결과를 후보 작업대에 병합
→ 완료 또는 추가 교정
```

## 실행

```powershell
python -B scripts/problem_solving_quality_next_loop_smart_web.py --open-browser chrome
```

또는 저장소 루트의 `start-psos-next-loop.cmd`를 실행한다.

## 기본 사용

1. 요청을 평소 말하듯 입력한다.
2. 화면 위의 추천 경로를 확인한다.
3. `해결 시작`을 누른다.
4. 시스템이 실행 방식을 자동 적용한다.

자동 선택 예시:

- 일반 설명이나 분석 → 일반 해결
- 최신 가격·뉴스·규정·현재 상태 → 최신 조사
- 상품 추천·구매·후보 비교 → 후보 비교
- 다른 AI가 사용할 프롬프트 제작 → 프롬프트 제작
- 코드·파일·웹페이지 수정 → 파일 변경

파일 변경은 안전 승인 때문에 허용할 파일 또는 폴더를 한 번 입력해야 한다. 이 경우 화면이 자동으로 고급 설정을 펼치고 필요한 입력칸으로 이동한다.

## 고급 설정

`고급 설정 보기`를 누르면 다음 기능을 직접 선택할 수 있다.

- 문제 해결: 일반 답변·조사·후보 비교·파일 작업
- 프롬프트 만들기: AI 한 번으로 Goal Ledger와 Brief를 설계하고 최종 조립
- 프롬프트 실험 · 수동 4단계: 단계별 결과를 비교하고 실패 지점을 진단하는 용도
- 답변·조사 / 파일 직접 수정
- 후보를 먼저 보여주고 중간 수정
- 최신 정보 검색 허용

수동 4단계에는 진행도, 현재 단계 강조, 전체 상태 복사와 초기화가 제공된다. 평소 작업용보다는 통합 방식과 비교하거나 어느 단계에서 품질이 무너지는지 확인할 때 사용한다.

## 후보 교정

후보 비교 경로는 첫 실행에서 정보원 정찰과 후보 작업대 생성 후 멈춘다. 결과 아래에서 짧게 교정한다.

- `candidate-002 제외`
- `전부 비쌈`
- `100g당 1000원 이하 더 찾아`
- `candidate-001 현재 판매 여부 확인`
- `현재 후보로 결론 내`

기존 후보로 처리할 수 있으면 재검색하지 않고, 부족한 구간만 동적 루프로 넘긴다. 부분 조사 결과는 후보 ID와 URL 기준으로 기존 작업대에 병합된다.

## 후보 병합 규칙

- 같은 candidate ID나 같은 URL은 기존 후보를 갱신한다.
- 새 후보에만 다음 `candidate-NNN` ID를 부여한다.
- 사용자가 제외한 후보는 새 조사에서 다시 유지 후보로 살아나지 않는다.
- 확인된 속성은 직접 출처와 함께 저장한다.
- 이미 검증된 후보는 약한 후속 정보로 `unverified` 상태로 후퇴하지 않는다.
- 부분 조사에서 후보 변화가 구조화되지 않으면 완료로 승격하지 않고 `partial`로 낮춘다.
- `VERIFY_COMPLETION`은 남은 후보가 있고 미해결 요구가 없을 때만 최종 완료가 될 수 있다.

## 경계

- 후보 교정 루프는 읽기 전용이다. 파일 변경은 승인된 기존 품질 실행으로 전환한다.
- next-loop 실행 기록은 canonical 품질 기록과 섞이지 않도록 `runs/next-loop-experiments/`에 둔다.
- 기존 품질 서버와 자동 추천 없는 통합 서버는 fallback으로 남긴다.
- 자동 분류는 화면의 빠른 실행 선택이며, 일반 문제 해결 내부의 PSOS 라우터 판단을 대체하지 않는다.

## 승격 전 확인

- 상품 구매: 후보 제외와 가격 상한 변경 후 부분 재조사
- 정보 조사: 공식 원문 우선으로 정찰 전략이 바뀌는지 확인
- 제작·설계: 기존 자산 후보를 보존한 채 접근법만 교정 가능한지 확인
- 프롬프트 요청이 별도 화면 전환 없이 통합 제작 API로 실행되는지 확인
- 파일 변경 요청이 허용 경로 없이 바로 실행되지 않는지 확인
- `awaiting_correction`과 `awaiting_information`이 최종 완료로 잘못 표시되지 않는지 확인
- 부분 재조사에서 새 후보와 갱신된 속성이 실제 작업대에 남는지 확인
